# Admin tournament results (T11)

`submitAdminTournamentResult` is a guarded server-only service for one singles athlete and one round. It accepts `AdminTournamentSubmissionInput`, resolves the session administrator and target program context, and passes only that verified actor to service-role RPCs. No injectable helper is exposed as a server action. T13 can wrap the service in an action.

A new tournament supplies its date range, site, surface, host and format. A new entry supplies a program roster ID, matching label, draw and positive seed (or null). An existing tournament or entry uses the fingerprints returned by `getAdminTournamentResultContext`. Existing entries must belong to the requested program and tournament and identify the selected singles athlete. Doubles entries are outside this one-player flow.

Round codes use the schedule's canonical `ROUND_ORDER`, which matches the live outcome constraint. Scores share T10's validation and preserve games, separate nullable tiebreak points, our-side-first identity, nullable legacy ad scoring and stopped-match winner semantics. Opponents belong to the saved round's match; the service does not rewrite the entry's shared opponent labels. Outcomes create no match. The complete request, roster identity, dates, format and score are checked before setup persists.

The operation UUID and item UUID are durable. Replays require the same actor, program and exact request. Setup atomically creates or links the event and entry once and records an entry/round target. Apply revalidates event/entry snapshots, roster eligibility and existing results, then atomically saves the result and audit or a durable failure. A saved result is terminal; retries skip it. A lost apply response is recovered through the status RPC. If status is unavailable, retry with the same IDs and request.

T10's reservation trigger already computes an empty round key for duals and the exact round for tournaments, so it is reused unchanged. Entry version locks serialize competing result writers. One round's reservation does not block another round. Coach scores, existing outcomes and legacy forfeits are never overwritten. Failed items permit ordinary progress, and a retry then refuses a result another writer saved. Identity or event edits become stale refusals.

New-entry setup and ordinary tournament entry inserts share an event advisory lock. The additive INSERT guard rejects a duplicate participant only when an existing entry is console-backed. Other ordinary entries retain their existing behavior. The profile ID and claimed user ID are compared as one athlete identity. Setup also refuses registering a new entry when any existing entry already represents that athlete; callers must select the existing entry. This is intentionally stricter than ordinary lineup management and avoids creating a second console result target for the same athlete.

Outcome INSERT uses the same tightly scoped transaction-local subject clearing as T10, with explicit `actor_user_id` and restoration before audit and after caught failures. Private markers alone cannot authorize authenticated writes. New tables have admin-only read RLS; mutation RPCs are service-role-only. No member action or existing live function/policy is replaced.
