Design · Video tab — the seek track's set readout
Hover a run of the track and it says which set it is.
The 3px seek lane is already split per set (setSegments, film-timeline.ts) but the runs are mute: nothing tells a viewer that the second run is the set they lost 4–6. This frame adds one dark readout over the lane — the box the room's court card already answers hover with (DARK_READOUT_CLASS / DARK_READOUT_STYLE) — on both mounts of FilmTrack: the shell player (film-player.tsx) and the room's transport (film-transport.tsx). No caret, no delay beyond --duration-fast, nothing grows under the cursor. Sample match throughout: Jordan Lee v Marcus Reid, film 1:42:18, entered score 6–4 4–6, and a third set on film that the entered score does not have.
A · Shell player (film-player.tsx l.679–685)
The tab's player at 720px. The lane sits in the bottom block (px-4 pt-7 pb-2, 6px above the 32px control row) over the player's own scrim. The readout hangs 6px above the lane's 16px box, anchored to the pointer's x and clamped inside the lane, and it never leaves the player's overflow-hidden frame.

E · Where the readout is not
SituationBehaviour
Pointer down / draggingCloses on pointerdown, stays closed until pointerup and a fresh pointer-enter (B3)
TouchNever opens: a touch pointer's first event is the pointer-down that starts a scrub (pointerType === "touch" is not needed as a guard, but is harmless). The set identity on touch is the board's
Room chrome collapsed (3s idle while playing)The transport goes pointer-events-none and fades; the lane fires pointer-leave, the readout closes with it. Focus on the lane holds the chrome up (the room's existing focusHolds) and the readout with it
Shell player in backgroundNot a hover surface — the room is over it. Nothing to do
Seek from elsewhere (a row click, ← →, D)On hover the box follows the pointer, so it is unaffected. On focus it follows the playhead into whichever run now holds it
EscNot handled here. In the room Esc is the exit key; blur closes the readout
